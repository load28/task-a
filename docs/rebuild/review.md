# 신규 설계 검토·검증 기록

검토일: 2026-09-26 · 대상: `docs/rebuild/` · 상태: 최초 계약 검토 기록

## 1. 요구와 범위

기존 구현을 계약의 근거로 사용하지 않고 R1–R4만으로 작성했다. AX는 고정 커밋의 공식 문서와 코드를 참고했다. 사용자 요청에 따라 이번 산출물은 계약·설계·구현 DAG이며 제품 코드 구현, 실행 기반 선정, 배포는 수행하지 않았다.

## 2. 문서 리뷰에서 반영한 내용

- source와 실행 leaf를 구분하고 외부 artifact의 등록·검증 증거를 정의했다. group은 명시적 필수 결과와 integration으로 완료를 판정한다.
- 포트 이름이나 계약이 같은 것만으로 변경 영향에서 제외하지 않도록 했다. 원 이력과 의미적 재사용 key를 분리하고 새 AdoptionRecord로 결과 재사용을 기록한다. 그래프 변경·결과 철회·fencing의 원자적 적용은 독립 구현 태스크 T15가 소유한다.
- 중단 후 snapshot 확보가 끝나기 전까지 captureHold로 공간 인계·삭제를 막는다. writer는 자식과 쓰기 권한이 있는 runner까지 포함한다. handle 없는 시작 intent 철회와 지연된 생성 요청의 거절을 backend 계약에 포함했다.
- 외부 효과의 성공 receipt는 호출 생략 근거로 다룬다. 검증 증거에는 신뢰된 발행 주체, 실제 검증 실행과 환경을 연결한다. 실행 환경 참조는 특정 플랫폼을 강제하지 않는다.

## 3. 기계적 검증

명령:

```sh
node docs/rebuild/validate-plan.mjs --self-test
```

결과: 19개 구현 작업, 4개 문서 source, 49개 작업 의존 관계가 순환 없이 연결된다. 계약 12개와 수용 시나리오 16개의 참조가 문서와 일치하고 최종 target T19에 모든 작업이 연결된다. 산출물 포트와 소유 범위가 유효하며 생성된 구현 계획 문서가 JSON과 일치한다.

잘못된 graph 6개도 검사했다. 순환, 없는 출력, 소유권 중복, 없는 계약, 완료 경로 누락, 없는 선행 작업을 모두 거절했다. 이 검증기는 문서 관리 도구이며 제품의 task runtime이나 계약 validator 구현이 아니다.

## 4. 아직 검증하지 않은 것

최초 문서 검토 당시에는 실제 backend의 격리·중단·재개, 저장 엔진의 장애 복구, planner의 자연어 분해 성능을 검증하지 않았다. 이후 AX 기반 구현의 실제 검증 범위는 [구현 상태](implementation-status.md)를 따른다. A01–A16은 앞으로 구현에서 통과해야 할 수용 조건이다. 문서 DAG 검사의 통과를 제품 동작의 통과로 해석하지 않는다.
