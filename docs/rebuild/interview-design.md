# 계획 이전의 Superpowers 인터뷰

## 목적과 계약

새 목표를 바로 실행 태스크로 분해하기 전에 사용자와 개념·목적·방향을 합의한다. 에이전트가 인터뷰를 진행하며 AX 실행 엔진의 데이터 모델과 actor 수명은 바꾸지 않는다.

- **D01 — 이해:** 목적·대상 사용자·성공 기준·제약을 확인하고 사실과 가정을 구분해 되짚는다. 질문은 한 번에 하나이며 미응답을 동의로 바꾸지 않는다. 이미 주어진 정보는 다시 묻지 않는다.
- **D02 — 경로:** Superpowers 원본의 spike/bounded/architectural 분류와 단계별 검토를 유지한다. 신규 프로젝트·구조 변경은 설계 문서 검토 전에 구현 Plan을 만들지 않는다. 상태 조회·중단·재개는 새 인터뷰를 시작하지 않는다.
- **D03 — 이력:** 원문·질문·실제 답변·방향 결정·미완료 단계·문서 경로와 검토 당시 해시를 대상 프로젝트에 기록한다. 다음 대화는 가장 이른 미완료 단계에서 시작한다. 변경된 문서에 과거 검토 답변을 그대로 적용하지 않는다.
- **D04 — 전달:** 검토한 설계에서 작은 결과 단위의 계획을 만들고 AX Plan으로 변환한다. 원본 계획의 인터페이스와 검증 조건을 전달한다. 계획 검토와 기존 실행 범위가 확보된 뒤에만 apply/run한다. 대화 기록은 보안 승인 토큰이 아니며 Go CLI는 대화 이력을 검증하지 않는다.

## 원본 채택

출처는 [obra/superpowers](https://github.com/obra/superpowers/tree/8ca22dba9a94f28898bbce59f2537ff4d87c747d), 고정 commit은 `8ca22dba9a94f28898bbce59f2537ff4d87c747d`다. [MIT 라이선스](../../engine/skill/upstream/superpowers/LICENSE)를 보존하고 brainstorming·writing-plans·시각 보조 도구 10개 원본 파일은 바이트 그대로 둔다. `node engine/verify-superpowers.mjs`가 해시를 검사한다.

| 원본 동작 | 연결 방식 |
|---|---|
| 맥락 확인·질문·방향 비교·부분 설계 검토 | 원본 brainstorming 지침을 그대로 읽고 사용자의 언어로 대화 |
| spec 작성·자체 검토·사용자 검토 | 원본 위치 기본값 유지, 실제 답변과 문서 버전을 프로젝트에 기록 |
| writing-plans의 작은 작업·인터페이스·테스트 | 원본을 읽고 계획을 작성하되 최종 실행 도구만 AX Plan으로 연결 |
| 필요할 때만 시각 보조 제안 | 원본 서버·템플릿·세션 인증 그대로 사용, 원본 환경 옵션으로 외부 브랜드 이미지 비활성화 |

Superpowers 전체 플러그인·다른 실행 스킬은 설치하지 않는다. 기존 원본이 참조하는 외부 스킬 중 brainstorming과 writing-plans만 로컬 파일로 연결하며, 제품 구현은 기존 AX 경로에 맡긴다. 문서 커밋·원격 게시·실행 권한은 세션에서 실제로 허용된 범위를 유지한다. 이 차이들은 [스킬 연결 문서](../../engine/skill/references/discovery.md)에 명시하며 원본 파일을 수정하지 않는다.

## 대화 흐름과 소유자

```text
부모 Codex ── 원문·범위 ──> 전담 task-agent
                              │
                      Superpowers 경로 분류
                              │
사용자 <── 질문 한 개·방향 비교·설계 ──┘
   │                          ▲
   └──── 실제 답변·문서 검토 ───┘
                              │
                  spec → writing-plans → AX Plan
                              │
                     기존 validate/apply/run
```

서브에이전트가 사용자 질문 도구를 사용할 수 없으면 부모가 질문을 전달한다. 에이전트는 사용자 대신 선택하지 않는다. `.task-agent/requests/<id>/discovery.md`는 다음 질문, 판단 근거, 검토된 문서를 잇는 대화 기록이다. 질문·문서 검토를 기다릴 때 actor를 만들지 않는다. bounded와 spike의 가벼운 경로는 원본대로 유지한다.

전역 설치기는 원본과 라이선스·시각 스크립트·참조 문서를 함께 복사한다. 기존 사용자 UI 메타데이터는 유지하고 갱신하는 파일과 역할은 백업한다. 스킬과 역할의 시작 안내가 discovery.md를 가리키며 일반 코드 수정 전체에 이 흐름을 강제하지 않는다.

## 검증과 한계

자동 검사는 원본 해시, 임시 CODEX_HOME 설치·백업·실행 권한·기존 메타데이터 보존, 설치된 래퍼의 AX context, 원본 시각 서버의 무인증 거절·세션 쿠키 화면 제공을 확인한다. 기존 엔진 테스트도 유지한다. 자동 테스트가 실제 인터뷰의 질문 품질이나 모든 모델의 지침 준수를 보장하지는 않는다. 실제 사용자와 끝까지 진행하는 인터뷰는 별도의 사용 검증이다.
