# Task Agent 신규 설계와 구현 기준

상태: **계약 유지·AX 원본 우선 구현으로 전환** · 작성일: 2026-09-26

사용자의 진행 지시에 따라 이 계약·설계를 기준으로 [greenfield 구현](../../greenfield/README.md)을 작성했다. 검토 때 만든 구현 DAG는 원본 계획으로 보존한다. 실제 완료 근거와 남은 범위는 [구현 상태](implementation-status.md)에서 별도로 관리한다.

작은 태스크를 계약으로 연결하고, 변경된 입력의 영향만 다시 처리하며, 각 태스크를 독립 공간에서 중단·재개하는 시스템을 처음부터 정의한다.

## 1. 이번 검토의 범위

요구사항의 근거는 아래 사용자 요구뿐이다. 기존 프로그램의 코드, 데이터 모델, 기능 목록, 문서, 운영 환경, 호환성은 이 설계의 제약으로 사용하지 않는다. 기존 구현의 일부를 유지하거나 이관한다는 가정도 두지 않는다.

- **R1 — 작은 작업:** 하나의 책임과 독립적으로 검증 가능한 결과를 가진 단위로 작업을 분해한다.
- **R2 — 변경 대응:** 요구·계약·입력·설계가 바뀌면 영향받은 작업만 재검증하거나 재작업한다.
- **R3 — 독립 공간:** 태스크마다 쓰기 공간과 실행 권한을 분리한다.
- **R4 — 중단과 재개:** 작업 상태를 보존하고, 이전 실행의 종료를 확인한 다음 안전하게 이어서 수행한다.

최초 설계에서는 AX를 참고 자료로 사용했다. 2026-09-27 결정으로 [AX 원본 우선 도입 계약·설계](ax-implementation-adoption.md)를 실행 기반의 최신 기준으로 삼는다. [engine/ax](../../engine/ax/)의 원본 설계·코드·내부 기술을 유지하며 불가피한 차이만 수정한다.

## 2. 계약 → 설계 → 구현 태스크 순서로 읽는다

1. [행동·데이터 계약](contracts.md): 시스템이 반드시 지켜야 할 불변식과 명령의 의미를 먼저 검토한다. `C01`–`C12`가 규범이다.
2. [설계](architecture.md): 계약을 네 경계로 배치하고, 변경·실행·복구 흐름과 검증 시나리오를 설명한다.
3. [구현 태스크 그래프](implementation-plan.md): 계약을 실제 구현 순서, 작은 작업, 산출물, 수용 조건으로 연결한다. [graph.json](graph.json)이 작업 정의의 단일 원본이다.
4. [AX 참고 근거](ax-reference.md): 원문에서 확인한 사실과 이 설계의 판단을 구분한다.

문서 사이에 충돌이 있으면 계약을 기준으로 설계를 수정한다. 계약 자체를 바꿀 때는 새 revision과 영향 분석이 필요하다. 구현 편의에 맞춰 계약을 조용히 완화하지 않는다.

## 3. 검토할 핵심 결정

| 결정 | 이 초안의 선택 | 판단할 내용 |
|---|---|---|
| 작업 분해 | 실행하는 leaf와 집계만 하는 group 분리 | 하나의 leaf가 결과와 검증 책임 하나를 갖는가 |
| 변경 처리 | 영향 후보를 먼저 차단한 뒤, 동일 입력은 재사용하고 나머지는 검증 또는 재작업 | 재사용 근거가 정확한 버전과 증거로 남는가 |
| 격리 | 환경 명세와 실제 쓰기 공간 분리, 공간당 writer 하나 | 다른 태스크의 가변 공간을 읽거나 쓰지 않는가 |
| 재개 | 파일·에이전트 세션 체크포인트에서 새 attempt 시작 | 실제 종료 확인과 외부 효과 처리가 빠지지 않았는가 |

아래 플랫폼 선정은 이전 구현의 이력이며 새 실행 기반을 제한하지 않는다. 실행 기반과 저장 엔진은 검토 시점에는 미선정이었다. `T02`에서 실제 환경을 확인한 뒤 Node 24·SQLite·로컬 CAS·Docker를 선정했다. 선정 근거와 지원 범위는 [실행 기반 결정](../../greenfield/platform-decision/README.md)에 기록한다.

## 4. 검증 범위

이 문서의 그래프 검증기는 구현 태스크 그래프의 참조, 순환, 계약·수용 시나리오 연결, 산출물 소유권을 검사한다. 설계의 의미적 타당성은 문서 리뷰로, 제품 동작은 별도 `A01`–`A16` 수용 시나리오로 검증한다.

```sh
node docs/rebuild/validate-plan.mjs
```

기록은 [검토·검증 기록](review.md)에 남긴다. 실제 실행 환경의 격리·복구를 검증하기 전에는 구현 완료나 운영 준비 완료로 표시하지 않는다.
