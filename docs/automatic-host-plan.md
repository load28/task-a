# OpenCode 서버 중심 최종 실행 설계

시각화 이후 합의한 실행 경계를 반영한다. Claude Code·Codex는 대화 인터페이스이며, OpenCode 서버의 native harness가 오케스트레이션과 실제 작업을 모두 담당한다.

## OpenCode가 전체 실행을 소유한다

사용자의 원문 요청을 OpenCode 세션에 전달한다. 기본 에이전트 `task-manager`가 일반 질문인지 개발 작업인지 판단하고, 기존 태스크를 검색하거나 새 태스크를 만든다. 필요한 수준까지 분해하고 실행 가능한 작업을 선택한다. 코드 수정, 검증, 결과 해석, 재시도, 통합 계획과 실패 진단까지 같은 서버에서 수행한다.

`task-worker`는 실제 구현과 검증을 수행하는 native subagent다. `task-planner`는 읽기 전용으로 분석·분해안·진단안·통합 시나리오를 작성하는 native subagent다. 기본 에이전트가 OpenCode의 `task` 도구로 위임한다. 계획 모드의 사용자 요청은 읽기 전용 에이전트에 전달한다. 역할별 도구 권한과 단계 제한은 OpenCode 설정에서 적용한다.

그래프 엔진 안에서 LLM 판단이 필요한 상황도 별도 하네스를 만들지 않는다. 기본 에이전트나 계획 에이전트가 그래프 맥락을 읽어 판단하고, 기본·작업 에이전트가 검증 가능한 제안과 결과를 Graph MCP로 제출한다.

## 그래프는 상태와 불변식을 소유한다

Task Graph MCP는 생성·검색·분해·작업 상태, Artifact/Contract, Integration/Bundle, Learning/Role 도구를 제공한다. `orchestrate_run`은 제공하지 않는다. 그래프 런타임에는 실행기나 모델을 연결하지 않는다.

엔진은 사이클, 참조, 허용된 상태 전이, 수락 조건, 정확한 Artifact 버전 조합을 검증한다. 태스크 검증과 통합 검증을 구분한다. 테스트 수행과 증거의 해석은 OpenCode가 담당한다. 그래프는 제출한 증거와 수락 조건을 기준으로 상태를 계산한다. 모델이 허위 증거를 제출하는 문제를 암호학적으로 증명하는 시스템은 아니다.

변경 요청마다 `operationId`를 받는다. 변경 결과와 receipt를 같은 SQLite 트랜잭션에 기록한다. 같은 ID·같은 인자는 기존 결과를 반환한다. 다른 인자로 ID를 재사용하면 거부한다. 프로젝트별 DB로 그래프를 분리하며 첫 프로젝트는 기존 DB 경로를 유지한다.

## 전달 계층은 실행 결정을 하지 않는다

UserPromptSubmit 훅은 요청을 영속 큐에 넣는다. 전달 서비스는 프로젝트와 OpenCode 세션을 연결하고 `promptAsync`를 호출한다. 같은 프로젝트에서 Claude와 Codex를 바꿔도 같은 서버 세션과 그래프를 사용한다. 같은 프로젝트의 독립 작업 요청은 전송 순서를 보존한다. 실행 중 대화는 우선 보류하여 호스트가 상태 확인·취소·조건 변경·새 작업·질문 답변 중 인터페이스 동작만 선택한다. 조건 변경은 native 실행 중단을 확인한 뒤 같은 세션에 원문을 보내며, 태스크 변경 판단은 OpenCode가 한다. 이 큐는 메시지 전달 순서만 관리하며 태스크 스케줄러가 아니다.

호스트 MCP에는 대화 제어, 상태 조회, 사용자 답변·승인 전달, 취소만 둔다. 프로젝트 경로는 기본적으로 자동 인식하며, 기존 명시적 DB 연결은 유지한다. 호스트의 직접 파일·터미널·다른 MCP 실행은 지원되는 PreToolUse 경로에서 차단한다. Stop은 결과 대기와 한 번의 전달만 처리하며, Stop과 대화 압축을 새 작업으로 보내지 않는다. 이전 대화와 thinking을 재수집하지 않는다.

전송 전 세션·메시지 ID를 저장한다. 수신 확인이 끊기면 OpenCode 메시지를 조회한다. 이미 수신한 메시지는 재전송하지 않는다. 수신 여부가 불명확하면 `uncertain` 상태로 후속 요청을 막고 사용자에게 취소·확인을 요청한다. 서버가 종료된 요청을 단순히 재실행하지 않는다.

## 운영 경계와 완료 판정

외부 OpenCode 서버 또는 자동 기동하는 로컬 OpenCode 서버를 사용한다. 로컬 모드에는 Docker가 필요하지 않다. 모델 인증은 OpenCode 서버가 소유한다. `claude` 지정 시 Anthropic 인증이 없으면 다른 모델로 대체하지 않고 오류를 반환한다.

OpenCode의 질문·권한 요청은 해당 기본 세션과 하위 세션에 한정해서 전달한다. 호스트는 사용자의 실제 답을 native API로 돌려준다. 권한 응답은 1회 허용 또는 거부만 지원한다. 취소는 해당 요청의 native 하위 세션까지 중단한다.

`completed`는 OpenCode 요청 응답이 종료됐다는 전달 상태다. 프로젝트의 검증 완료 여부는 Task Graph의 `verified`/`integrated`와 증거로 판단한다. 도구 호출만 남은 응답, 단계·출력 제한, 재시작으로 끊긴 응답을 성공으로 간주하지 않는다. 네트워크 대기와 사용자 승인 대기는 완료가 아니다.
