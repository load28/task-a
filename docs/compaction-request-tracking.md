## 요청 경계는 전달 서비스가 소유한다

`relay_turns`는 전달 순번, 요청 ID, 네이티브 세션 ID, 전달 메시지 ID를 SQLite에 보존한다. 실제 전송 전에 기록하며 같은 메시지의 재시도는 중복 등록하지 않는다. 자동 실행 지속 요청도 별도 전달 경계로 남긴다. 기존 설치는 보존된 최근 전달 메시지를 이전하고, 덮어써서 이미 사라진 과거 경계는 추측해 복원하지 않는다.

OpenCode 세션은 이 전달 서비스가 생성·소유한다. 한 전달 턴의 관측 범위는 해당 메시지부터 같은 세션의 다음 등록된 전달 메시지 직전까지다. 범위 안에서는 내부 사용자 메시지, 압축, replay, 변경된 `parentID`와 관계없이 실행 응답을 추적한다. 특정 문구나 내부 `compaction_continue` 표지를 사용하지 않는다. 서로 다른 ID 생성기의 정렬 차이를 피하기 위해 메시지 생성 시각으로 정렬한다. 경계를 찾을 수 없으면 다른 요청의 기록을 추측해 포함하지 않는다.

OpenCode의 압축은 별도 요약과 후속 사용자 메시지를 생성한다. 그 내부 구현은 [OpenCode 소스](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)에서 확인할 수 있다. 요약 응답의 `finish=stop`은 작업 완료가 아니므로 제외하고, 요약 자체의 오류는 보존한다.

## 실행·완료·복구 규칙

압축 이후 새로 생성·재개된 태스크 ID, 진행, 오류와 최종 응답을 기존 요청에 누적한다. 다음 전달 턴이 시작된 이전 요청에는 현재 세션의 실행 상태나 질문을 붙이지 않는다. 관리자 응답 종료와 그래프 검증 완료는 계속 별도로 검사한다.

구버전이 `interrupted`로 저장한 요청은 상태 조회 시 동일한 전달 경계로 다시 관찰한다. 원본 요청을 재전송하거나 작업을 복제하지 않는다. 새 기록에서 실제 실행 중임이 확인되면 관측을 계속하며, 그래프 검증이 확인되지 않은 작업은 완료 처리하지 않는다.

Python 실행 지침은 입력 스냅샷의 외부 링크 차단을 유지하면서 `python -m venv --copies .venv`와 명시적인 가상환경 실행 경로를 사용한다. 검증 명령은 저장소의 실제 CLI 진입점을 확인하도록 한다.

- 실패 당시 작업자 이미지에서 `venv --copies`로 만든 환경의 입력 스냅샷이 성공함을 확인했다. 전체 타입 검사와 회귀 테스트 170개가 통과했다.
