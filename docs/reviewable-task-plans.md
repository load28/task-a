# 조사 후 태스크 설계를 승인하는 흐름

새 개발과 기존 기능 변경 모두 먼저 읽기 전용으로 현재 코드, 관련 태스크 상태와 필요한 자료를 조사한다. 조사를 시작하기 위한 계획 승인을 먼저 요구하지 않는다. 조사 결과로 실제 태스크와 의존 관계를 설계한 다음 해당 버전의 계획을 제시한다.

각 태스크에는 담당 책임, 목표, 수정 파일 범위, 조사 근거, 구체적인 설계, 입력, 산출물, 완료 기준, 검증 방법과 위험을 포함한다. 기존 기능 변경은 기존 동작과 변경 후 동작 및 재사용·교체·재검증 대상을 설명한다. `taskSpec.design`에 조사 근거와 설계를 저장하고 호스트는 이를 단계 이름으로 축약하지 않는다.

공개 계획 생성·수정 도구는 상세 필드를 필수로 검사한다. 조사 근거는 확인한 파일 경로나 자료 URL과 발견 내용을 담아야 한다. 엔진이 근거의 진실성까지 자동 판정하는 것은 아니며 모델은 실제 조사 결과를 기록해야 한다. 과거 간략 초안은 읽을 수 있지만 Graph MCP에서 승인하려면 상세 수정안을 먼저 만들어야 한다. 내부 복구용 과거 계획 데이터는 계속 지원한다.

승인 대기 중에는 해당 수정안으로 태스크를 생성하거나 기존 실행을 교체하지 않는다. 수정 요청은 새 리비전으로 저장하고 다시 검토한다. 승인된 명세를 그대로 재개할 때는 재승인을 요구하지 않는다. 실행 중 새로운 방향·범위·설계 변경이 필요해지면 다시 조사하고 상세 수정안을 제시한다.

검증: 계획 생성·수정의 상세 데이터 보존, 재접속 후 동일 리비전 재승인, 반복 호스트 투영, 상세 설계가 없는 초안의 실행 승인 차단을 전체 테스트에서 확인한다.
