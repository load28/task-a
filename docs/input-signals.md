# 코드 해시 기반 Push/Pull 실행

## 변경을 알리고 실행 직전에 입력을 고정한다

코드 산출물 게시 시 실제 작업공간의 파일 트리를 SHA-256으로 계산한다. 설명문이나 호환성 라벨로 코드 동일성을 판단하지 않는다. `.git`을 제외한 파일, 경로, 실행 권한, 링크를 포함하며 미커밋·미추적 파일도 포함한다. 외부 경로를 가리키는 심볼릭 링크와 해시 계산 중 변경되는 트리는 거부한다. 현재 범위는 전체 작업공간이므로 설치된 의존성도 검사 비용에 포함된다.

게시된 해시가 바뀌면 직접 소비 태스크에 영속 시그널을 기록한다. 대기 중 여러 변경은 하나로 합친다. 선행 작업이 안정되고 실행을 점유할 때 입력 버전, 코드 해시, 명세, 환경 식별자를 고정한다. Pod는 해당 입력 작업공간을 읽기 전용으로 가져오고 실제 파일 해시를 다시 검사한 뒤 명령을 실행한다. 여러 입력의 코드 통합은 담당 구현·통합 태스크가 수행한다.

## 실행 종료 확인과 결과 채택을 분리한다

입력이 바뀐 실행은 즉시 결과 채택 권한을 잃는다. 중단 요청을 SQLite에 저장하고 실제 Pod 종료 또는 중지 상태를 확인해야 다음 실행이 시작된다. 재실행마다 새 물리 인스턴스를 생성하고 자신의 이전 PVC 또는 아카이브에서 부분 작업을 복원한다. 논리 태스크와 모든 물리 실행의 연결 이력을 유지한다.

결과 제출 시 고정한 입력과 현재 입력을 같은 데이터베이스 트랜잭션에서 비교한다. 환경 변경과 이전 토큰의 늦은 결과도 차단한다. 코드 결과는 성공한 실행의 파일 해시 영수증 및 입력 스냅샷과 연결한다. 환경 식별에는 이미지 참조, 실행 명령, 저장소 설정, Secret의 UID/resourceVersion을 사용한다. Secret 값은 저장하지 않는다. 이미지 태그가 가리키는 원격 이미지의 변경까지 감지하는 방식은 아니므로 재현성이 필요한 환경은 이미지 digest를 사용한다.

## 변하지 않은 후속 결과는 재사용한다

선행 작업이 재실행 중이지만 후속 작업의 입력은 아직 바뀌지 않았다면, 후속 작업이 제출한 결과를 보류한다. 선행 작업이 같은 코드 해시를 게시하면 보류 결과를 재실행 없이 채택한다. 다른 해시를 게시하면 보류 결과를 격리하고 후속 작업을 다시 실행한다. 무관한 작업에는 시그널을 보내지 않는다.

검증 결과 재사용은 코드 해시와 입력·명세·환경 동일성이 확인될 때만 허용한다. 코드 해시가 없는 과거 결과는 재사용하지 않는다. 문제를 원인 담당에게 돌려보내는 책임 기반 수정 흐름은 유지한다. 동일 코드의 메타데이터 버전만 바뀐 경우 해시 동일성을 검증하여 불필요한 후속 실행을 피한다.

## 검증과 운영

`task_signal_status`로 변경 시그널과 중단 상태를 확인한다. `task_signal_reconcile`은 중단 확인, 실행 준비, 보류 결과 채택을 진행한다. 호스트 루프에서도 이 조정을 수행한다. 파일 편집 자체를 감시하는 방식이 아니라 산출물 게시 시 변경을 전파한다.

```sh
npm run check
TASK_INSTANCE_CONTEXT=kind-task-agent-local \
TASK_INSTANCE_NAMESPACE=task-agent \
TASK_INSTANCE_IMAGE=task-agent-instances:signals \
npm run test:signals:kubernetes
```
